## 2. 业务模块划分
**目的**：产出可直接用于用例分组（测试套件/目录）的层级结构。
**做法**：以“业务逻辑内聚性”为标准划分，不是直接照搬前端菜单。
**输出格式**：树状列表 + 简要说明
**示例**：
```
1. 用户管理
  1.1 用户新增
  1.2 用户列表与查询
  1.3 用户编辑与详情
  1.4 用户导入（含异常处理）
  1.5 用户状态管理（启用 / 停用 / 注销）
2. 角色与权限
  2.1 角色创建与编辑
  2.2 权限分配
  2.3 权限校验（页面级+数据级）
...
```

**注意事项**：
- 每个叶子模块就是一个用例组的候选名。
- 如果一个功能横跨多模块（比如“审批流程”），要么提升为独立模块，要么在使用处标注关联，避免同一功能散落各处。

### 3. 核心业务逻辑梳理
**目的**：让测试设计者一眼看懂主流程、分支流程、状态变化——这是用例设计前最重要的理解层。

**推荐组合使用三种方式**（根据业务复杂度选择其一或混合）：

#### a. 业务流程图
- 适合：有明显“开始→步骤→结束”的流程
- 标注：角色操作 + 系统行为 + 判断节点

#### b. 状态流转图 / 状态表
- 适合：对象有明显生命周期（订单、审批单、任务）
- 标注：前置状态 → 触发动作 → 后置状态 → 约束条件

#### c. 核心规则表
- 适合：业务计算逻辑、校验逻辑较多
- 格式：缩进树或用竖向箭头图。

示例：
```
审批金额 <= 1000
├── 直接上级审批
└── 无需抄送
审批金额 > 1000
├── 上级审批
└── 抄送财务主管
    ├── 若为采购类，额外抄送采购总监
    └── 若金额 > 5000，需总监加签
```

## 4. 功能点测试清单
**目的**：输出可直接指导用例设计的原子化功能点（不是用例本身，而是“要测什么”）。
- “异常场景提示”只做列举，不做详细用例设计，保证清单不臃肿。
- “所属模块”直接关联第2章的模块树，确保分组对应。
- 重点模块功能可以加上原文引用，方便回溯

**示例**：
```
# 功能点测试清单

## 用户管理
### 用户新增[PRD 2.1 用户新增]
- 创建单用户：填写全部必填字段，保存成功（P0）
- 字段校验：用户名含特殊字符，提示错误（P1）
- 字段校验：用户名重复，提示已存在（P0）
- 角色分配：创建用户时选择角色，自动继承权限（P0）
### 用户列表与查询[PRD 2.2 用户新增]
- 默认分页展示：按创建时间倒序，每页10条（P1）
- 按用户名搜索：完整/模糊匹配（P0）
- 按状态筛选：启用/停用/全部（P1）
- 多条件组合查询：无结果时显示空状态提示（P2）
### 用户导入[PRD 2.3 用户导入]
- 上传合法 csv（≤500条）：全部导入成功，列表更新（P0）
- 上传合法 xlsx（≤500条）：与 csv 表现一致（P0）
- 边界：刚好500条，成功（P0）
- 边界：501条，前端提示且不调用接口（P1）
- 异常：文件格式为 .txt，提示错误（P1）
- 重复用户处理：导入文件中含有已存在用户名 ->（待确认策略，暂为“跳过并汇总报告”）（P0）
- 权限校验：非管理员看不到导入入口（P0）
```
