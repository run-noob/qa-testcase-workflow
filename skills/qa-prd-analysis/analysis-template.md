## 3. 组件级交互说明
- 每个页面的组件分配编号：`{SystemModule}-{PageCode}-{ComponentCode}`
- *按照页面从上到下、从左到右的视觉顺序描述页面模块和组件，重点关注交互逻辑*
- **每个UI元素的描述必须包含：视觉特征 + 交互逻辑 + 状态变化**
- **[页面区域/模块名称]**
  - **[组件名称/区块]**
    - **功能描述**：该组件的主要用途
    - **视觉特征**：*仅描述关键视觉特征，如"主按钮"、"卡片式布局"、"网格排列"等UI类描述词*
    - **交互逻辑**：
      - 触发条件：什么情况下用户会操作此组件
      - 用户操作：点击、悬停、输入等
      - 即时反馈：操作后的即时视觉/状态反馈
      - 状态变化：组件自身状态变化（如激活/禁用）
      - 后续影响：是否引发其他组件变化或页面跳转
    - **数据状态影响**：
      - 不同数据状态下组件的表现差异（如有数据/无数据/加载中/错误）
      - 用户权限导致的显示/操作差异
    - **业务规则**：相关的业务逻辑约束
示例：
```
### 3.1 TRADE-LIST (交易列表页)

#### 3.1.1 TRADE-LIST-FILTER (筛选区域)
- **编号**: TRADE-LIST-FILTER
- **功能描述**: 用户可按类型、状态、时间筛选交易订单
- **视觉特征**: 顶部横向排列的下拉框和日期选择器
- **交互逻辑**:
  - 触发条件: 用户需要缩小订单范围
  - 用户操作: 选择筛选条件后点击"搜索"按钮
  - 即时反馈: 按钮显示 loading 状态
  - 状态变化: 列表区域刷新
  - 后续影响: 触发 `TRADE-LIST-TABLE` 数据更新
- **数据状态影响**: 
  - 无筛选结果时显示空状态提示
- **业务规则**: 
  - 时间范围不得超过90天

#### 3.1.2 TRADE-LIST-TABLE (订单列表)
- **编号**: TRADE-LIST-TABLE
- **功能描述**: 展示符合条件的交易订单
- ...
```

## 4. 核心业务流程

- 为流程分配编号：{SystemModule}-FLOW-{FlowName}，并包含以下基本信息
- **[流程名称]**（如：创建交易）
  1. **触发入口**：用户从哪里开始此流程
  2. **步骤分解**：每个步骤的用户操作和系统反馈
  3. **验证规则**：各步骤的数据验证和错误处理
  4. **完成状态**：流程完成后的结果和后续操作
示例：
```
### 4.1 TRADE-FLOW-CREATE (创建交易流程)
- **流程编号**: TRADE-FLOW-CREATE
- **触发入口**: 从 `TRADE-LIST` 点击"创建交易"按钮
- **步骤分解**:
  1. 进入 `TRADE-CREATE` 页面
  2. 填写 `TRADE-CREATE-FORM` 表单
  3. 点击 `TRADE-CREATE-SUBMIT` 按钮
  4. 跳转至 `TRADE-DETAIL` 查看新订单
- **验证规则**: 
  - 表单字段验证规则（参考 `TRADE-CREATE-FORM` 组件说明）
- **完成状态**: 订单创建成功，状态为"待接受"
```

## 5. 测试关注重点

- **核心业务流程**：验证产品最主要的用户路径是否畅通以及是否满足PRD定义的核心功能目标
- **边界条件**：针对输入框、数值范围、时间区间、分页等临界值的检查。如：最大字符长度、数值的最小值/最大值、列表翻页的最后一页等，这是最容易出现逻辑错误（如大于还是大于等于）的地方

**重点关注以上两点**，以下几点根据不同需求而定作为补充
- 异常/错误场景：验证系统在非正常操作或环境下的健壮性。如：网络错误、接口错误、前端操作异常、系统异常等
- 权限控制：登录态和不同角色权限在的交互差异性
- 兼容性要求（如 PRD 提及）：确保产品在不同软硬件环境下的表现一致。如响应式和多端差异
- 性能/安全要求（如 PRD 提及）：针对非功能性需求的专项验证。
